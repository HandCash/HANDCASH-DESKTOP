# Background wallet work and UI responsiveness

Development shipment, 2026-11-19. No public release tag.

- Activity reads item-output projections in a worker without transferring large remittance records to the UI thread.
- Item transaction/script and origin-art decoding run through the compute worker. Worker failure defers decoding rather than falling back to heavy UI work; timeout terminates the worker.
- Collectables projection yields to input, rejects stale account results, and releases completed list ownership before the next page starts.
- IndexedDB transaction-request scans select matching index keys; tag hydration batches reads in one transaction.
- Durable storage removes only identical shell-backed large local mirrors; market cache quota failures do not suppress updates.

Verification: 13 focused files / 86 tests passed, TypeScript and diff checks passed. The local Linux build was installed with its prior app backed up and wallet data untouched. User reports: “works great”. The fresh log spans 17:00:30–17:03:31 UTC and contains 14 stalls, largest 3,925 ms, versus the earlier regression's maximum 35,078 ms. Workloads differ, so this does not prove every background stall or crash cause is eliminated.
