# BRC coverage of the wallet

Generated by `node scripts/jev-brc-map.mjs` on 2026-10-17 with Jev (`jev-1.13.0`). Do not edit by hand.

**480 units** scanned (474 non-test modules under `src/wallet`, `src/contracts`, `src/ports`, `electron`, plus 6 HandCash-only bridge method families) against **228 BRCs** (bsv-blockchain/BRCs `upstream/master` plus our draft branches). Jev judged **243 of them to be features**; 177 implement at least one BRC, 181 cross a boundary another implementation must agree on, and **10 have an interoperable part no BRC specifies but should** (9 new BRCs, 1 extensions).

**How to read this.** Code collected every fact (headers, exports, BRC numbers named in source, the catalog); Jev made only judgments: feature or plumbing (≥ 0.5), area, interoperable (≥ 0.5), and for each candidate BRC whether the module *implements* it (builds, parses, verifies or enforces what it defines, ≥ 0.5) or only *uses* it through other code. Candidates are Jev's top catalog picks plus every BRC the file names. Mapping and gap questions see each BRC's abstract and section headings; every proposed gap is then checked against the full text of up to four specs (those it implements or names, the closest one, and the three sharing the most distinctive words) and dropped if one already specifies it. Feature names come from module names; descriptions are each module's own header comment.
